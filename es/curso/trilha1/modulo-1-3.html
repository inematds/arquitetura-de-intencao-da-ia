📁 Carpetas y archivos: el hogar del proyecto

Toda solución de IA vive en algún lugar: un conjunto de carpetas y archivos dentro de una computadora. Parece banal, pero es la base física de todo. Un proyecto bien organizado es como una casa ordenada: encuentras lo que necesitas en segundos. Un proyecto desordenado es como un cajón lleno de chucherías: todo está ahí, pero nadie encuentra nada. No necesitas talento para eso, solo una convención sencilla y el hábito de respetarla.

🏠 La regla de oro de la organización

Una carpeta por proyecto. Dentro, carpetas por tema (entrada, salida, notas). Nombres en minúsculas, sin espacios ni tildes, separando las palabras con guiones. Esta convención por sí sola resuelve el 90% del desorden y funciona igual en tu computadora, en el servidor y en GitHub.

Una estructura sencilla y clara

📁 meu-jarvis/ # la carpeta del proyecto
  ├── entrada/ # lo que llega (mensajes, archivos)
  ├── saida/ # lo que responde el sistema
  ├── anotacoes/ # la memoria del proyecto
  └── leiame.txt # qué es esto, en 5 líneas

Ejemplo ilustrativo de estructura de carpetas — adapta los nombres a tu proyecto. Lo importante es el patrón, no estos nombres exactos.

⌨️ La terminal: perder el miedo

El terminal es esa pantallita negra de las películas de hackers. Asusta porque parece que hay que memorizar mil comandos, pero la verdad es más sencilla: el terminal es solo una conversación con la computadora por texto, en lugar de hacer clic con el mouse. Escribes una orden, presionas Enter y te responde. El objetivo aquí no es convertirte en especialista en línea de comandos: es perder el miedo, entender que es una herramienta amigable y saber pedir las pocas cosas que importan.

terminal — meu-jarvis
tú ▸ cd meu-jarvis # entrar en la carpeta del proyecto
tú ▸ ls # listar lo que hay aquí dentro
entrada/ saida/ anotacoes/ leiame.txt
tú ▸ pwd # "¿dónde estoy?"
/home/voce/meu-jarvis

Recreación ilustrativa de una terminal, no es una captura de pantalla real. Los comandos solo sirven para mostrar el ritmo "escribo → Enter → respuesta".

💡 Consejo práctico: tres comandos bastan para empezar

No necesitas memorizar nada. Para empezar, tres órdenes resuelven casi todo: cd (entrar en una carpeta), ls (ver lo que hay) y pwd (saber dónde estás). Con esto ya puedes navegar. El resto se lo pides a la IA — y así es fácil entender lo que escribió.

cd carpetaEntra en una carpeta (como hacer doble clic en ella)
cd ..Vuelve una carpeta atrás
lsLista los archivos y las carpetas donde estás
pwdMuestra el camino completo desde donde estás

🌿 Git y GitHub: versionar es guardar versiones

Imagina un videojuego en el que puedes guardar la partida en cualquier momento y volver a cualquier partida guardada cuando te equivoques. Eso es exactamente lo que el Git hace con tu proyecto: cada vez que "guardas", conserva una foto completa de todo; esto se llama commit. O GitHub es el lugar en internet donde se guardan esas fotos, lejos de tu computadora. Git es la herramienta que toma la foto; GitHub es el álbum en la nube. El control de versiones no es cosa de programadores avanzados: es solo el hábito de guardar con historial.

El recorrido de un trabajo hasta la nube

1

Trabajas

Edita archivos en la carpeta del proyecto, como siempre lo hiciste.

2

Haz uno commit

Toma una «foto» del estado actual y escribe una frase sobre lo que cambió: "agregué la carpeta de notas".

3

Haz uno push

Envía las fotos a GitHub. Ahora tu trabajo está seguro en la nube, con todo el historial.

El ciclo, en tres líneas

git add . # "quiero guardar lo que cambié"
git commit -m "o que mudou" # toma la foto + descríbela
git push # envía a GitHub

Comandos ilustrativos: los pegarás una vez y los repetirás siempre. No hace falta memorizarlos: necesitas entender que cada línea es un paso de «guardar con historia».

📜 Historial y colaboración: la memoria del proyecto

El control de versiones no sirve solo para que no pierdas el trabajo. Cuando el historial está en GitHub, se convierte en la memoria del proyecto: puedes ver quién cambió qué, cuándo y por qué. Y eso permite algo esencial: que varias personas (o varias IA) trabajen en el mismo proyecto sin pisarse. Casi nunca se crean soluciones reales en solitario. El historial es lo que permite volver atrás con seguridad y confiar cuando otra persona hace cambios.

✓ Con historial (GitHub)

  • ✓"¿Se rompió? Vuelvo a la versión de ayer en 1 minuto."
  • ✓Se puede ver quién cambió cada línea y por qué.
  • ✓Dos personas trabajan en el mismo proyecto sin sobrescribirse.
  • ✓El proyecto tiene memoria: nada se pierde al "guardar encima".

✗ Sin historial (archivos sueltos)

  • ✗projeto_final_v3_AGORA_VAI.zip
  • ✗Nadie sabe cuál es la versión correcta.
  • ✗Uno guarda encima del otro y el trabajo desaparece.
  • ✗"Funcionaba la semana pasada" —y no hay forma de volver atrás.

🗺️ Entender el mapa, no dominarlo todo

Aquí está la liberación de este módulo: tú no necesitas dominar la infraestructura como un ingeniero sénior. Necesitas entender el mapa. Un taxista no construyó las calles ni sabe de ingeniería del asfalto, pero conoce la ciudad y llega adonde necesita. Esa es tu meta con las carpetas, la terminal y Git: saber lo suficiente para decidir, pedir lo correcto y no depender de nadie para recorrer el camino.

🧭 Mapa × dominio: la diferencia que libera

  • Dominar sería saber cada comando, cada detalle, cada caso raro: años de estudio, y no es tu trabajo.
  • Entiende el mapa es saber qué existe, para qué sirve y cuándo usarlo: semanas de familiarización, y eso es exactamente lo que necesita el arquitecto.
  • La IA completa el resto: ella escribe el comando difícil; tú entiendes lo que escribió y decides si está bien.

💡 Consejo práctico: la pregunta correcta para la IA

Cuando te trabes con la infraestructura, no preguntes "¿cómo hago todo esto?". Pregunta: "explícame en una frase qué hace este comando y cuál es el riesgo de ejecutarlo". Tú sigues al mando de la decisión: la IA se convierte en tu copiloto técnico, no en tu jefe.

🧰 El entorno del arquitecto: configurar una vez

Por último, el arquitecto arma un entorno de trabajo — el conjunto mínimo de herramientas con las que construyes. No es mucho: un editor para escribir, la terminal abierta al lado, una cuenta de GitHub y el hábito de organizarte. Preparas este entorno una sola vez y te ahorra horas en todos los proyectos siguientes. Es como ordenar la mesa de trabajo antes de empezar: cinco minutos al inicio te ahorran todo el día buscando herramientas.
